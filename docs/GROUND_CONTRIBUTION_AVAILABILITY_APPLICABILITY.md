# Contribution-contextual Availability Applicability

## Adopted human contract

A canonical relation is required, without a scalar verdict. Resource identity
and matching time do not imply applicability. Its subject is a Contribution /
Binding context, and its target is an existing stable pair of selected-source
aggregation policy and interpretation policy. Runtime specification is the sole
declaration authority; social authorization is not modeled.

## Stable declaration checkpoint

`buildAvailabilityEvidenceContract` wraps the exact existing GROUND-185 policy
and its nested GROUND-180 aggregation policy. Identity contains their two keys.
Absent interpretation policy is not a contract. An explicit empty mapping policy
is still an existing contract; this does not imply current evidence is resolved.

`declareContributionAvailabilityApplicability` requires an existing GROUND-177
quantity evaluation state, a contract, and a specification naming both the exact
contribution context and contract. Resource equality is a structural check only.
The context retains candidate, need, requirement set, requirement, binding,
resource, contribution declaration and its evaluation instant. It excludes the
quantity evaluation key and both current evidence dimensions. The contract and
relation contain no current GROUND-187 state key, value, result or evaluation.

Updating current evidence does not require redeclaration. Changing either policy
requires a new specification. Changing the contribution subject is not an
evidence-only update. The function declares one relation; it introduces no
exclusivity, conflict-resolution or cardinality rule between separate relations.

This layer does not resolve current evidence, compose dimensions, re-run source
selection, aggregation or interpretation, or declare overall readiness.

## Boundaries

Quantity authority remains GROUND-177 / 169 / 175. Availability authority remains
GROUND-187 and its upstream chain. No source trust, effective quantity or
availability, free quantity, reservation subtraction, allocation, consumption,
deliverability, verification, satisfaction, readiness, feasibility verdict,
can_execute, execution, substitution or cross-binding aggregation is derived.
